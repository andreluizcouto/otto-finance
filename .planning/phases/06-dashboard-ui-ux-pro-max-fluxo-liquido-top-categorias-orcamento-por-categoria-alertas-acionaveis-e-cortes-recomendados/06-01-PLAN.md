    - `share_pct` representa participação da categoria no total de saídas do período.
    - `delta_pct` compara categoria com janela imediatamente anterior de mesma duração.
    - `budget_progress` cruza categorias com tabela `budgets` e calcula progresso percentual.

1. Em `backend/modules/dashboard/services.py`, adicionar helpers explícitos:
   - `def _build_flow_summary(df: pd.DataFrame) -> dict[str, Any]`
   - `def _build_category_insights(df: pd.DataFrame, all_transactions: list[dict], start_date: date, end_date: date, cat_by_id: dict[str, Any]) -> list[dict[str, Any]]`
   - `def _load_user_budgets(client: Client, user_id: str) -> dict[str, float]`
   - `def _build_budget_progress(category_insights: list[dict], budgets_by_category: dict[str, float]) -> list[dict[str, Any]]`

2. Regras concretas de cálculo:
   - `inflow_total = sum(amount where amount > 0)`
   - `outflow_total = abs(sum(amount where amount < 0))`
   - `net_flow = inflow_total - outflow_total`
   - `net_flow_status = "positive" if net_flow > 0, "negative" if < 0, "neutral" if == 0`
   - `share_pct = round((current_amount / total_outflow) * 100, 1)` com fallback 0 quando total_outflow=0
   - `trend = "up"` se delta_pct > 0, `"down"` se < 0, `"flat"` se == 0 ou None
   - `progress_pct = round((spent_amount / monthly_limit) * 100, 1)` quando monthly_limit > 0, senão 0 com status `no_limit`
   - status budget: `on_track` (<80), `warning` (>=80 e <100), `exceeded` (>=100), `no_limit` (sem limite)

3. Ajustar a consulta de categorias para incluir visibilidade real:
   - trocar `eq("is_default", True)` por filtro que inclua padrões + categorias do usuário (`is_default=true OR user_id=user_id`).

4. Em `get_dashboard_payload(...)`, incluir no retorno:
   - `flow`
   - `category_insights` (top 5 por `current_amount` desc)
   - `budget_progress` (mesmas categorias do insight, com limite quando existir)
   - preservar chaves antigas (`kpis`, `trend`, `category_totals`, `recent_transactions`) para compatibilidade.
